# 两阶段阅读与验收

关键词：review、receipt、coverage、Stage 1、Stage 2、断点续读。

脚本创建材料和候选切分，不负责模型理解。启动后默认执行两个阶段；每批读完立即写回，不等待额外批准。阅读范围是 manifest 的明确来源。

## 操作循环

1. verify 检查实际文件、原生成员、来源定位和知识引用。review 返回实时阶段与缺口。
2. review --next --limit 8 返回下一批未读单元及 read receipt。阶段 auto 在 initial 已处理后切到 deep。
3. 实际读取完整 text 和 context。next_text_offset 非空时继续 read --unit ID --offset OFFSET；合并多次 receipt 后才能把完整单元标记已读。大量结果用 query 的 next_offset 分页。工具输出若被宿主截断，不得据此标记完整阅读；缩小批次/字符数继续。
4. visual 单元必须用宿主实际图像工具打开 image_input.path。read 返回路径和 receipt 不证明看过图像；保存具体观察、工具、rendition_id 和 hash。小字用 crop，从保留的 PDF 高分辨率导出；cellview 展示隐藏单元格时须说明是派生证据图。
5. 调用 record，填写 expected_revision、model、receipt_ids、reads，以及发现的知识 records。初读状态 read，深读状态 deep_read；无法读/理解写 gap 和具体原因。
6. 继续 review --next，直到阶段待处理数为零。initial 完成后直接开始 deep。中断从已提交队列恢复；review --recover 只回收已退出写进程的锁并重建派生索引。

## Stage 1：全文初读

遍历所有必读单元，包括短条款、空单元格、代码、批注、隐藏数据、原生图形和连接、视觉内容页；同一图片多个出现位置保留上下文。建立概览、术语/别名候选、对象、候选关系和问题。内容来源、排版、结构推断分别标识，不把源目录层级盲当业务层级。

段落是上下文容器，clause 是句子/条款候选；候选切分可修订。表格的前两行仅是标题候选，read 的 table 上下文也列出行、合并继承和父表。必要时读取完整 table 单元及其段落 ID，不仅阅读搜索命中的一句话。CSV 多行单元格保留原换行。Excel 空白不是零或 No。

## Stage 2：全文深读

逐句/条款解释其性质、指代、角色、行为、对象、前提、否定、数量、单位、例外和结果；标题和标签说明其范围，排版或空白说明其解释边界。原生数据核查隐藏状态、公式与缓存；不擅自执行计算。原生连接端点不自动表示业务方向。

复杂术语/概念保存定义、作用域、别名、用法、关系和未知；对象保存身份、字段、角色、状态及约束，不自动变成数据库实体。根据实际内容建立知识，不强迫每个词产生卡片。每条重要结论绑定具体出处，查找相关段落、附件和反证。

每单元必须有实际深读记录或缺口；允许一条初读记录包含多个确实读完的单元。深读共享解释时仅组合语义相同的单元，notes 要说明共同含义和各出现位置差异；不能用“都读了”笼统覆盖整份文档。

## 验收状态

- completed：该阶段所有必读单元都有实际阅读记录，无缺口。
- completed_with_gaps：单元均已处理，但含明确不可读/未完成项；gap 不计入 actually_read。
- pending：还有 unread 或 needs_revalidation，不能宣称阶段结束。
- ready / ready_with_gaps：两个阶段都已处理且证据完整性检查通过，可进入有范围的问答。

源缺失定义/冲突可形成已读单元中的 unknowns，而不是伪造答案。故障、未知材料、无图像宿主记录 gap。遗漏处理与准确理解分别验收，semantic_accuracy 不自动赋值。阅读声明不能自动证明模型确实理解，需真实抽查、反例和业务复核。

## v3 的细节核查

read 的 interpretation_annotations 展示删除线、显式关闭、隐藏文字、样式来源、待确认修订、域和批注；这些提示不属于原文，引用仍用 text_range。存在格式未知、删除线或显示差异时核查页面，不自动将其解释为批准、取消或删除要求。

按适用内容核查角色/动作/对象/作用域、前提、否定、例外、数量、单位、期限、输出与反证，不机械填满模板。重要规则须联合表头/合并格、附件、图示及批注，记录决定性证据与未核验边界。标题、标签和空格说明上下文即可，不强迫建立知识卡片。

初读和深读均按小批次提交，文字与视觉可分别读取，避免工具截断。同一单元的深读要有解释或缺口，不能用统一已读声明批量代替理解。图像工具记录仍是宿主声明，不能因脚本接受就宣称实际看过。

review 将业务未知 business_unresolved 与技术 gaps、needs_revalidation_records 分开。未知可存在于已读单元；不能为获得ready而填补来源未定义项。
